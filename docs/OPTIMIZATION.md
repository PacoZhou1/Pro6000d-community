# 优化机制与证据

## 卡间通信

默认B12X的小消息归约在该平台微测偏慢。真实模型切换NCCL使C1 verifier约55.3→64.7steps/s，随后使用混合阈值：小于等于8KB保留B12X，禁用twoshot，其他适用路径走NCCL，大消息DMA。NCCL4通道在C8上有收益；不能把微测带宽直接换算成端到端收益。

关闭IOMMU单独没有加快默认B12X，因此不把整个提升归给P2P开关。当前设置SYS确保NCCL允许跨root的P2P，但配置变量本身不能代替实际拓扑、执行计数及有效吞吐验证。

## MoE激活与小批量BF16投影

W4A4→W4A16保持同一NVFP4权重，BF16激活路径将verifier64.75→74.82。它是精度路径选择，必须单独标注。真正的同精度源码改动是 `homelab_dense_fused.py`：严格匹配RTX6000D/156SM、TP4投影形状和M1–4，重用上游CuTe BF16内核，权重加载时准备，CUDA graph重放不允许临时编译；其他形状保留原路径。

适配q_b_proj、o_proj与KDA融合q/k/v/beta/fa投影，(N,K)为4096×1536、4096×4096、4096×2048、6288×4096。MTP3的C1 target验证常为M4，因此不能只优化普通decode M1。

第一版有54项真实权重数值/回放/回退和6项编译图检查；第二版四卡真实TP切片48项检查，复制fa输出逐字节一致。对应verifier约+2.15%和+1.51%；C8基本持平。验证脚本在qualification，历史结果并非发布时重跑。API算术、查找、图片、工具与工具历史5项曾通过；这不是通用准确率评测。

## mHC资源生命周期

`mhc-lifetime-v1.py`把breakable graph持有输出的方式改为弱绑定，scratch生命周期仍保留。资格检查有216次bitwise输出对比；这是内存/图资源问题的修正候选，不是新算术实现。更大graph成功捕获后prefill反而约−0.83%，因此日常版保留capture256。相关文件diff、数值报告和CUDA复现脚本已随仓库保存。

## 没有采用的方向

batch16384比8192慢；DMA1片比2/4片慢；把prefill大消息强行走PyNCCL约−10.5%，A/B/A回退恢复；DMA图复用微测收益未充分变成完整模型收益。未完成资格检查的scheduler与通信压缩原型没有进入公开部署配置。

CPU turbo开启，现有GPU轨迹并不支持大量CPU下发空档是主要根因；通信等待也会计入GPU busy。重叠kernel累计时间不能当墙钟百分比相加。prefill仍是待优化项。

准确表述是“推理引擎源码、GPU算子选择/调度与图资源生命周期的适配”。不是修改Linux内核，也没有新写CUDA/PTX数学内核；不能把现有上游CuTe/B12X算法作为自研成果。
