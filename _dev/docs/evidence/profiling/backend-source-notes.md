# vLLM 0.31.0 后端选择：固定源码与包证据

范围：Qwen3.6-27B-FP8、RTX PRO 6000 Blackwell（SM120），固定 vLLM `v0.31.0` / [`db9527a46873454610df6dbedf79a36d6bf1a7f6`](https://github.com/vllm-project/vllm/tree/db9527a46873454610df6dbedf79a36d6bf1a7f6)。本文区分源码允许、当前镜像实测选择和待验证的性能；不将候选后端写成已取得收益。

## FP8 block W8A8 的选择与排除

- 固定源码的量化键为 `fp8_block_w8a8`，`linear_backend_per_quant` 优先于全局 `linear_backend`；后端注册表依次考虑 FlashInfer/DeepGEMM dynamic、DeepGEMM、CUTLASS、B12X、Marlin、Humming、Triton、Torch，并检查各自 `is_supported` / `can_implement`。见 [注册与优先级](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/__init__.py#L237-L249)、[CUDA 候选列表](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/__init__.py#L455-L475)、[量化键与选择日志](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/__init__.py#L714-L740)。单因素 A/B 的显式形式是 `--kernel-config '{"linear_backend_per_quant":{"fp8_block_w8a8":"b12x"}}'`；同一处也可设 `cutlass` 或 `triton`。CLI 语法见 [v0.31 serve 文档](https://docs.vllm.ai/en/v0.31.0/cli/serve/)。
- 现有 MTP4 基础镜像的启动日志（主实验记录）实际报告 `Selected CutlassFp8BlockScaledMMKernel for Fp8LinearMethod`；Nsight 归类中的 CUTLASS blockwise kernel 亦见本目录 [`mtp4-nsys-summary.json`](mtp4-nsys-summary.json)。启动日志还报告对 `model_type=qwen3_5_text` 的 Blackwell DeepGEMM 自动禁用，理由是 E8M0 scale 精度退化。所以在该镜像上 `auto → cutlass` 不是有效的对照切换。固定源码明确把该模型类型排除于 Blackwell DeepGEMM，见 [DeepGEMM 兼容规则](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/utils/deep_gemm.py#L28-L53) 和 [block-FP8 实现检查](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/scaled_mm/deep_gemm.py#L55-L82)。
- CUTLASS 是有 SM120 专用实现的基线：[入口的 SM100+ 与 CUDA ≥12.8 条件](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/csrc/libtorch_stable/quantization/w8a8/cutlass/scaled_mm_entry.cu#L161-L175)、[SM120 派发](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/csrc/libtorch_stable/quantization/w8a8/cutlass/scaled_mm_c3x_sm120.cu#L9-L20)、[按 M 分段的 tile 启发式](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/csrc/libtorch_stable/quantization/w8a8/cutlass/c3x/scaled_mm_blockwise_sm120_fp8_dispatch.cuh#L253-L281)。因此 profiler 中 `cutlass_3x_gemm_fp8_blockwise` 名称与选择日志一致；[`mtp4-nsys-summary.json`](mtp4-nsys-summary.json) 是本机分析输出，kernel 累计时长不能直接等同端到端延迟占比。
- 固定 vLLM 的 FlashInfer **block-FP8 GEMM** 检查精确计算能力 `90`，并调用 `fp8_blockscale_gemm_sm90`；`is_device_capability(90)` 是精确匹配，故 SM120 不满足此路径。见 [FlashInfer 条件](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/utils/flashinfer.py#L1175-L1214) 与 [设备能力接口](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/platforms/interface.py#L470-L490)。这只排除其 block-FP8 GEMM，**不排除** FlashInfer attention 或 GDN prefill。
- [Triton block-FP8 实现](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/scaled_mm/triton.py#L159-L179) 是可独立测的同类 W8A8 候选；[PyTorch block-FP8 实现](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/scaled_mm/pytorch.py#L269-L335) 限于 SM90。Marlin 是 A16 权重路径并涉及权重重排，不能当作相同算术的直接 A/B，见 [Marlin 检查](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/scaled_mm/marlin.py#L29-L116)。

## B12X 版本和隔离实验

固定 vLLM 的 [B12X 适配器](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/scaled_mm/b12x.py#L49-L99) 要求 CUDA SM12x、`b12x.gemm.blockscaled` 可导入且报告支持、动态激活 `(1,128)`、权重 block `(128,128)`、输入/输出维度为 128 的倍数；[权重处理和预热](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/kernels/linear/scaled_mm/b12x.py#L101-L170) 在同文件。固定源码 [extra 依赖](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/setup.py#L1550-L1552) 与 [v0.31 B12X 文档](https://docs.vllm.ai/en/v0.31.0/features/quantization/b12x/) 指向官方 `b12x==1.3.0`，不是 1.5.0。

| 包 | 官方发布元数据里的 CuTe DSL 依赖 | 对现有镜像的含义 |
| --- | --- | --- |
| [b12x 1.3.0](https://pypi.org/project/b12x/1.3.0/) | `nvidia-cutlass-dsl` 与 base/core/cu12/cu13 库均 `==4.6.2` | 与镜像的 `4.7.1` 不同；同时 [FlashInfer 0.7.0.post1](https://pypi.org/project/flashinfer-python/0.7.0.post1/) 的 `cu13` extra 要求 DSL `>=4.7.0a0`，按 extras 解析存在硬冲突。 |
| [b12x 1.5.0](https://pypi.org/project/b12x/1.5.0/) | DSL 与上述库均 `==4.7.1` | 与现有镜像的 DSL `4.7.1` 匹配，但**不是**固定 vLLM 官方 extra 所 pin 的版本。 |

当前基础镜像安装 torch `2.13.0+cu130`、FlashInfer `0.7.0.post1`、DSL `4.7.1`，没有 B12X；见 [`mtp4-runtime.json`](mtp4-runtime.json) 和包依赖归档 [`b12x-packages.json`](b12x-packages.json)。研究时核对了 1.5.0 wheel 对 `is_supported` / `mm_block_fp8` 的导出与调用签名，符合固定 vLLM 适配器的调用形式；这只是**静态 API 兼容检查**，不代表初始化、数值或性能通过。此 wheel 的 SHA256 为 `4b6635e93ce672db1415cca1817c81eab461a245fb96a5e2de7efa2e36a36114`；派生镜像 `sha256:52f2384487e25d934da8928d9f2759fdeb57886bba348b7883fc84dce3ca0f48` 的本地记录见 [`b12x-image.json`](b12x-image.json)。隔离比较须在该**同一派生镜像**上分别显式选 `cutlass` 与 `b12x`，保持模型、请求、缓存 dtype 和其余包一致；先检查启动日志实际选择和响应正确性，再比较稳定运行的性能。B12X 是 Python wheel + CuTe DSL JIT，首轮编译/预热时间不属于稳定性能。

## GDN 与 BF16 GEMM 的边界

- 固定 [Qwen GDN prefill 后端选择](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py#L93-L154) 在当前 head_k_dim=128、CUDA 13 的 SM120 可选 FlashInfer；`cutedsl` 限于 SM100，`triton` 是另一条 FLA 路径。现有日志显示 `Using FlashInfer GDN prefill kernel (requested=auto, head_k_dim=128)`，解码另选 `cuda`，见 [`mtp4-runtime.json`](mtp4-runtime.json) 及 [decode 选择](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/mamba/gdn/qwen_gdn_linear_attn.py#L509-L533)。GDN 对照可单独使用 `--gdn-prefill-backend triton`，不应和 FP8 GEMM 后端同时更改。
- Qwen 模型以 [`ParallelLMHead`](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/models/qwen3_5.py#L349-L360) 经 [`LogitsProcessor`](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/logits_processor.py#L138-L181) 计算 logits。对未量化权重，[unquantized GEMM 派发](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/vocab_parallel_embedding.py#L72-L83) 走默认路径。固定 vLLM 的 [FlashInfer BF16 小 M 快速路径](https://github.com/vllm-project/vllm/blob/db9527a46873454610df6dbedf79a36d6bf1a7f6/vllm/model_executor/layers/utils.py#L100-L134) 限于 SM100 家族，故没有找到可通过现成 CLI 在 SM120 专门替换 BF16 lm_head GEMM 的路径。Nsight 中的 BF16 CUTLASS kernel **尚未通过算子归因证明属于 lm_head**；在归因前不应将改 lm_head 当成已验证靶点，`--linear-backend` 也不能据此声称会替换它。
