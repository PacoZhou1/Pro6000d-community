# RTX PRO 6000 Workstation 的可用单元与 FP8 优化边界

结论：对这张 **RTX PRO 6000 Blackwell Workstation Edition 96 GB（GB202、计算能力 12.0／SM120）**，文本 LLM 的 FP8 矩阵乘已在 Tensor Core/CUTLASS 路径上；另一个可编程机会是用 CUDA SM 的 warp、寄存器、shared memory 和缓存，把矩阵乘前的动态量化、归约和数据准备做得更省。它不是把 token “解码”交给视频解码器或光追核心。[NVIDIA 产品规格](https://www.nvidia.com/en-in/products/workstations/professional-desktop-gpus/rtx-pro-6000/)、[NVIDIA MIG 支持表（确认 GB202/12.0/96 GB）](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/supported-gpus.html)。

| 硬件/机制 | 这张卡上的适用性 | 对本轮 FP8 的判断 |
|---|---|---|
| 第五代 Tensor Core | 产品规格明确列出；正常 CUDA Graph trace 已看到 `cutlass_3x_gemm_fp8_blockwise`，固定 vLLM 在 SM120 派发 CUTLASS FP8 GEMM。[NVIDIA 规格](https://www.nvidia.com/en-in/products/workstations/professional-desktop-gpus/rtx-pro-6000/)、[CUTLASS SM120 文档](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/blackwell_functionality.html#blackwell-sm120-gemms)、[本地固定派发源码](../gemm-targeted/source/csrc/libtorch_stable/quantization/w8a8/cutlass/c3x/scaled_mm_blockwise_sm120_fp8_dispatch.cuh)。 | 不是等待“启用”Tensor Core；改 tile/调度须对比现有有效基线。已测大 M tile、Split-N 未获收益，见[定向 GEMM 记录](../../09-targeted-gemm.md)。 |
| CUDA warp/SM、shared memory、L2 | NVIDIA 的计算能力表支持 warp reduce、硬件异步复制和 L2 residency 管理；SM120 为 32 线程 warp，shared memory/寄存器资源须按 12.x 而非 SM100 配置。[CUDA 计算能力表](https://docs.nvidia.com/cuda/cuda-programming-guide/05-appendices/compute-capabilities.html)。 | 适合试验量化 scale 的 warp 归约、访存合并和少量中间数据保留；改变线程组织可能影响 occupancy、数值舍入或缓存行为，仍须实测。 |
| 异步复制与 TMA | CUDA 文档列 TMA 为 CC 9.0+ 的 global/shared 异步搬运，受地址/长度对齐要求约束。[CUDA 异步复制](https://docs.nvidia.com/cuda/cuda-programming-guide/04-special-topics/async-copies.html)。固定 SM120 CUTLASS dispatch **已经**使用 `KernelTmaWarpSpecializedBlockwisePingpongSm120` / `...CooperativeSm120` 调度，且 trace 中有对应核名。[固定源码](../gemm-targeted/source/csrc/libtorch_stable/quantization/w8a8/cutlass/c3x/scaled_mm_blockwise_sm120_fp8_dispatch.cuh)。 | 不能把“打开 TMA”记为新优化；只能针对具体量化/数据准备路径验证流水与访存改动是否减少其耗时。 |
| `tcgen05`/Tensor Memory | NVIDIA PTX 支持表把 `tcgen05.mma`、Tensor Memory 分配等列给 SM100/101 系列，未列 SM120；NVIDIA CUTLASS 对 SM120 列出 `mma.sync.aligned` 路径。[PTX 特性表](https://docs.nvidia.com/cuda/parallel-thread-execution/#changes-in-ptx-isa-version-8-8)、[CUTLASS SM120](https://docs.nvidia.com/cutlass/latest/media/docs/cpp/blackwell_functionality.html#blackwell-sm120-gemms)。 | 不把 B200/SM100 的 TMEM、`tcgen05` 性能或用法套到此工作站卡。SM120 有自己的 Tensor Core 路径。 |
| NVDEC / NVENC | 本卡列有 4 个第六代视频解码器及 4 个第九代视频编码器；NVIDIA API 明确处理压缩视频码流及视频帧。[产品规格](https://www.nvidia.com/en-in/products/workstations/professional-desktop-gpus/rtx-pro-6000/)、[NVDEC API](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvdec-video-decoder-api-prog-guide/index.html)、[NVENC API](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.0/nvenc-video-encoder-api-prog-guide/)。 | 能帮助多模态**输入视频**的编解码；不执行 Transformer 的 token decode、FP8 GEMM 或动态量化。 |
| 第四代 RT Core | 产品列出 RT Core；NVIDIA 描述其用途为光线追踪的 BVH 遍历及射线/几何相交。[产品规格](https://www.nvidia.com/en-in/products/workstations/professional-desktop-gpus/rtx-pro-6000/)、[NVIDIA 光追说明](https://developer.nvidia.com/discover/ray-tracing)。 | 稠密文本 GEMM/采样不具有该类射线计算结构，不是可直接调用的 LLM 加速器。 |
| MIG | NVIDIA 官方支持表对 Workstation Edition 标明**最多 4 个实例**；MIG 把 SM 和内存资源切为隔离份额，面向并行工作负载的 QoS。[支持表](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/supported-gpus.html)、[MIG 介绍](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/introduction.html)。 | 可能隔离多服务干扰，但不会给单个已独占整卡的 27B 请求增加算力/带宽；本轮没有确认或变更服务器 MIG 配置。 |

本轮候选是**已有融合的 SiLU + 乘法 + 每 128 元素 FP8 block 量化核**的 warp-group 线程组织改动，优化 Tensor Core GEMM 之前的数据准备与 scale 归约；它不替换 BF16 `lm_head`，也不引入 FP4。该名称组在两份正常 Graph prefill 捕获中各占全部 GPU kernel duration 之和的 **4.316%/4.319%**。这是整个核零成本消失的乐观算术上限，**不是整模延迟或 tok/s 的承诺**。候选守卫只命中 `M≥256` 且布局匹配的调用，`M=5` decode 走原核，须检查回退正确性。另一个独立的 `per_token_group_quant_8bit_register_kernel` 在 prefill/decode 分别约占 **1.565%/1.394%**，属于未来单独验证的机会，不能算作当前候选收益。[逐核机会分析](profile-opportunities.md)、[完整原名与分母](profile-opportunities.json)。
