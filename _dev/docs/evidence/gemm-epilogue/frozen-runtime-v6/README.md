# Isolated runtime proof entry

These files are opt-in for an **isolated** fixed-image vLLM 0.31 experiment. They do not change the repository's production services. No GPU run has validated them yet.

Place this directory first on `PYTHONPATH`. Set `PRO6000D_EPILOGUE_MODE=probe` or `baseline`, an absolute `PRO6000D_EPILOGUE_EVIDENCE_DIR`, and absolute `PRO6000D_EPILOGUE_V2_SITECUSTOMIZE` pointing to the previously validated V2 sitecustomize. Keep the V2 environment (`PRO6000D_FP8_FUSION_ENABLE=1`, library path and SHA256) in both arms. Python auto-imports only one `sitecustomize`, so this entry explicitly executes the V2 entry. The packed weight is produced after vLLM's `BaseModelLoader.load_model` returns, before warmup/compilation. It is held as a non-persistent buffer alongside canonical weight; `baseline` never calls it.

The fixed [PostGradPassManager](../source/installed/vllm/compilation/passes/pass_manager.py) appends `ActivationQuantFusionPass` before the experimental proof pass. The proof pass uses the official `add(CallableInductorPass(...))` API and only records graph nodes, edges, tensor metadata, module-stack keys and GEMM→fused-quant paths. Its UUID changes the compilation cache identity. `analyze_proof.py` reads those snapshots offline and deliberately marks weight identity and replacement eligibility **unproven** until a real graph contains sufficient information. Old `fp8-fusion/b-cache-audit.json` records generated-code line hashes but its generated Python files were not preserved; it does not establish adjacency or module identity.

`candidate` currently fails at import: the CUDA C ABI and a truly fused FX replacement have not passed compile/graph/numeric checks. A later adapter must replace the GEMM+activation-quant chain with the kernel agent's GEMM epilogue quantization and a pack step; wrapping the old GEMM and old activation kernel together would not meet the optimization goal. The provisional **v2** C ABI exports `gateup_quant_abi_version() == 2`, `gateup_quant_temp_scale_bytes(M)`, `gateup_quant_fp8(out_fp8,out_scales,temp_fp8,temp_scales,A,Bpacked,As,Bspacked,M,swizzle,workspace,workspace_bytes,stream)`, and `gateup_quant_last_error()`. The two temp buffers and CUTLASS workspace must be caller-owned, distinct per invocation, and allocated before CUDA Graph capture; no global mutable scratch. `temp_scales` uses CUTLASS's native SF128 layout, while `out_scales` uses downstream stride `(1,M)`. This ABI is **not yet compiled or validated**. Retain canonical B for small-M and all guard failures. Before activation, require real target/MTP FX graph proof, explicit mapping from canonical B input to packed buffer, output single-consumer proof, fake/meta + CUDA op implementation, and actual launch/numeric checks.

Local syntax validation: `python3 -m py_compile runtime/*.py`. This does not establish runtime compatibility or numerical correctness.
