# Candidate runtime contract (opt-in, v4 witness validated)

The isolated `sitecustomize.py` supports `probe`, `baseline`, and `candidate`. Both A/B keep the prior V2 activation quantization and retain canonical plus paired gate/up weights. Candidate mode fails startup unless a separately supplied validated SHA256 equals the mounted ABI v2 library SHA256. The v4 isolated direct-op smoke and real-model witness passed their stated checks; this does not establish end-to-end speedup or authorize production deployment. The later cooperative v5 kernel failed strict synthetic numerical checks and is excluded.

The fixed vLLM `PostGradPassManager.configure` adds `ActivationQuantFusionPass`. This runtime appends a read-only proof callback and, in candidate mode, a structural rewrite through the official `add(CallableInductorPass(...))` API. The real `model-witness-v4-meta-fixed` startup compiled 21 FX graphs and rewrote 20 gate/up fragments. Each matching fragment has `auto_functionalized<_C.cutlass_scaled_mm>` → BF16 `[M,34816]` → `auto_functionalized<pro6000d_fp8.silu_and_mul_per_block_quant>`. The BF16 tensor has one data consumer (quant) plus a shape-only `aten.sym_size.int` user. The rewrite redirects the shape user to A, inserts the functional `pro6000d_gateup.fused(A,B,As,Bs)` op, replaces the two quant outputs, then eliminates the old GEMM and BF16 allocation. `fx_matcher.py` requires exact operation, operand metadata, graph edges, exclusive allocation readers, quant arguments, and output `getitem` indices; an unmatched graph is left unchanged. `real_fx_matcher_selfcheck.py` reconstructs the saved JSON adjacency and confirms 20 matches survive the new reader guards, while an injected extra reader on each of three allocation sites is rejected. This is a CPU audit of saved real graphs, not a new model run.

Packing occurs after model loading/postprocessing and before compilation. The startup registry retains strong references to each canonical `(B,Bs)` pair and its packed pair, keyed by device plus both data pointers. The opaque op receives canonical B/Bs as explicit arguments and rechecks their device, dtype, shape, stride, storage offset and storage base. A shape or module name alone never authorizes a candidate launch. The single-load isolated process supports main-model 64 plus MTP 1 module; model reload is unsupported. A lookup miss, small M, or wrong device capability takes the canonical GEMM+V2 path and is explicitly labelled fallback at Python dispatch time. This label is not a CUDA Graph replay count.

The native branch permits only `256 < M <= 32768`, SM120, FP8 A `[M,5120]`, FP32 A scales `[M,40]` with stride `(1,M)`, canonical FP8 B `[34816,5120]`, and FP32 B scales `[272,40]`. It outputs FP8 `[M,17408]` contiguous and FP32 `[M,136]` with stride `(1,M)`. ABI v2 performs a quantizing GEMM epilogue followed by FP8 pack; it does not materialize the BF16 `[M,34816]` intermediate. The ABI queries native temp-scale and workspace sizes for each M/swizzle. Output, paired-FP8 temp, native-scale temp, and workspace are allocated per invocation on the current stream. No fixed 128 MiB-per-layer workspace is reserved. The v4 real-model prefill Nsight witness matched 130 fused GEMM plus 130 pack kernels to 260 successful **direct** launches and none to graph replay. Small-M fallback has a direct-op synthetic smoke; CUDA Graph behavior has separate standalone synthetic candidate probes. Neither is evidence of real-model graph replay.

`runtime-smoke-v1.json` records direct-op M257 registered dispatch and two canonical fallbacks equal to independent canonical GEMM+V2 outputs for synthetic inputs. `model-witness-v4-meta-fixed/integration-summary.json` records 65 canonical/packed identities and 11,589,593,600 extra packed bytes in the isolated model. The fresh A/B/A API and same-KV-pool comparison remains a separate decision gate. The existing original 27B/9B/ASR services remain stopped until the user requests them; embedding remains running. This runtime does not manage those services.
