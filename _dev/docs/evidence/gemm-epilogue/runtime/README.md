# Isolated runtime proof entry

These files are opt-in for an **isolated** fixed-image vLLM 0.31 experiment. They do not change the repository's production services. The v4 witness has completed a real-model startup, FX rewrite and direct-launch diagnostic; it has not established an end-to-end speedup or production suitability.

Place this directory first on `PYTHONPATH`. Set `PRO6000D_EPILOGUE_MODE=probe` or `baseline`, an absolute `PRO6000D_EPILOGUE_EVIDENCE_DIR`, and absolute `PRO6000D_EPILOGUE_V2_SITECUSTOMIZE` pointing to the previously validated V2 sitecustomize. Keep the V2 environment (`PRO6000D_FP8_FUSION_ENABLE=1`, library path and SHA256) in both arms. Python auto-imports only one `sitecustomize`, so this entry explicitly executes the V2 entry. The packed weight is produced after vLLM's `BaseModelLoader.load_model` returns, before warmup/compilation. It is held as a non-persistent buffer alongside canonical weight; `baseline` never calls it.

Each model load writes `startup-pack-<pid>-<run_id>-<event_index>.json`; a separate `startup-pack-<pid>-<run_id>-summary.json` accumulates main-model and MTP counts/bytes without overwriting the first event or a prior run with a reused PID. Per-module canonical/packed weight and scale device addresses are recorded for later identity checks. FX shape/stride dimensions are stored as expressions (`str(SymInt)`), preserving dynamic symbols without specializing them.

The fixed [PostGradPassManager](../source/installed/vllm/compilation/passes/pass_manager.py) appends `ActivationQuantFusionPass` before the experimental proof pass. The proof pass uses the official `add(CallableInductorPass(...))` API and records graph nodes, edges, tensor metadata, module-stack values and GEMM→fused-quant paths. Its UUID changes the compilation cache identity. In `model-witness-v4-meta-fixed`, all 21 saved real FX graphs compiled, with 20 strict matches and 20 rewrites; 65 canonical/packed module identities were checked. `real_fx_matcher_selfcheck.py` rehydrates those saved graph relationships and confirms the new single-reader guards retain 20 matches while rejecting an injected extra reader on each allocation. This CPU audit checks recorded adjacency, not model execution. Old `fp8-fusion/b-cache-audit.json` does not establish adjacency or module identity.

`candidate` is an opt-in experimental path. It requires `PRO6000D_EPILOGUE_LIBRARY` plus matching `PRO6000D_EPILOGUE_LIBRARY_SHA256` and **separately supplied** `PRO6000D_EPILOGUE_VALIDATED_LIBRARY_SHA256`; without exact equality startup fails. `PRO6000D_EPILOGUE_SWIZZLE` defaults to 8. The versioned ABI exports `gateup_quant_abi_version() == 2`, `gateup_quant_temp_scale_bytes(M)`, `gateup_quant_workspace_bytes(M,swizzle)`, `gateup_quant_fp8(out_fp8,out_scales,temp_fp8,temp_scales,A,Bpacked,As,Bspacked,M,swizzle,workspace,workspace_bytes,stream)`, and `gateup_quant_last_error()`. It computes a quantizing GEMM epilogue plus FP8 pack without the old BF16 intermediate. The two temp buffers and queried workspace are per invocation. The isolated `runtime-smoke-v1.json` proves registered M257 and unregistered/M5 fallback output equality for its synthetic inputs. The v4 real-model prefill Nsight witness records 130 fused GEMM and 130 pack kernels, all 260 matched to successful **direct** launches; none are graph replay. Small-M fallback is shown by the direct-op synthetic smoke; CUDA Graph behavior is shown only by separate standalone synthetic candidate probes, not by the real-model witness. The subsequent cooperative v5 kernel fails strict synthetic numerical comparisons and is not validated for this runtime.

`fx_matcher.py` recognizes the actual GEMM→BF16→V2 fused quant structure after the official pass, including the shape-only `sym_size` user and exclusive allocation readers. In candidate mode `fx_rewrite.py` replaces that chain with a functional opaque op and retargets `sym_size` to A. Compile ranges ending at M=256 or below retain the original graph. The op looks up packed B/Bs by both canonical storage pointers and checks tensor layout; unregistered or unsupported calls execute the canonical GEMM+V2 quant path and are labelled fallback. Optional `PRO6000D_EPILOGUE_DISPATCH_EVIDENCE=1` writes first Python dispatch/capture records, **not** CUDA Graph replay or request launch counts. The v4 trace establishes real direct candidate launches; A/B/A API latency and output checks are a separate decision gate. Do not run these tools in production service processes.

Local syntax validation: `python3 -m py_compile runtime/*.py`. This does not establish runtime compatibility or numerical correctness.
