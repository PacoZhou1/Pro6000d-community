# Paired gate/up FP8 epilogue experiment (v6 evidence)

The fixed large-M CUTLASS block-FP8 GEMM uses 128×128×128 tiles and writes BF16 `[M,34816]`. The existing fused SiLU/quant kernel then reads that BF16 tensor and writes FP8 `[M,17408]` plus FP32 scale `[M,136]` (stride `(1,M)`). A 128-column CTA cannot see matching gate/up columns because the two original halves are 17,408 columns apart.

This candidate keeps canonical weights for fallback and adds a one-time packed copy in both A/B arms. For group `g` in `0..135`, packed rows `256g:256g+128` are original gate rows `128g:128g+128`; packed rows `256g+128:256g+256` are original up rows `17408+128g:17408+128g+128`. Weight block scales `[272,40]` follow the identical 128-row permutation; input FP8 and input scales do not change. A CTA owns one packed 256-column group and the same M tile, so it owns each gate/up pair once.

The 64×256×128 mainloop uses the fixed SM120 block-scale granularity `(M1,N128,K128)`. The final v6 test uses the Cooperative schedule; earlier v3 used Pingpong and v4 used a 32×256 Pingpong tile. A 64×256 epilogue tile holds both halves. Its visitor BF16-rounds each FP32 accumulator separately, then evaluates the fixed FP32 `gate/(1+expf(-gate))*up`, takes max-absolute over each 128-product group, applies the fixed scale floor `1/(448*512)`, divides/clamps and converts to E4M3. The visitor writes FP8 `[M,34816]` with valid products in each group's first 128 columns and zero in the second 128. A second pack kernel produces contiguous FP8 `[M,17408]` and copies native CUTLASS scale to the fixed column-major scale layout. It does **not** write or read a BF16 GEMM result. The extra FP8 temporary and pack kernel are included in timing and memory accounting.

The builder verifies SHA256 of the fixed vLLM dispatch and bundled CUTLASS headers before generating shadow copies, compiles only `sm_120a`, and does not modify the installed library. It extends the bundled scale visitor from SF64 to SF128. The v6 fix is a **single generated-header line**: Cooperative SF128 uses `WarpsPerSF=2` rather than v5's `4`, invoking the existing `warp_idx ^ 4` two-warp reduction with eight local fragments per scale. Its generated visitor shadow differs from v5 on that line alone. The same Cooperative BF16 GEMM, inverse-packed, matched the official GEMM at all 8,947,712 elements in each of five M257 input distributions. An identity visitor that skipped SiLU exposed v5's scale-path fault: versus the Pingpong identity control, v5 differed at 6,810,443 FP8 bytes and 57,485 scales on M257 normal. After the one-line v6 correction, the complete candidate passed the fixed 12-case numerical and changed-input CUDA Graph gates. This pins the observed v5 failure to the visitor/SF path rather than the GEMM mainloop; it does not prove every Cooperative layout is valid.

The Cooperative M64 tile remains outside fixed CUTLASS's declared support domain: upstream asserts CTA M≥128. Our isolated builder shadow-relaxes that assertion to M≥64, and retains the exact original-header SHA guard. v6 is therefore an experimental binary, not a generic CUTLASS fix. The final library SHA256 is `e4039ddc95fa3b56f02743357b7a7193156dc500c5d8804bb77ebd3af85450d6`.

ABI v2: `gateup_quant_abi_version() == 2`; `gateup_quant_temp_scale_bytes(M)`; `gateup_quant_fp8(out_fp8, out_scales, temp_fp8, temp_scales, A, Bpacked, As, Bspacked, M, swizzle, workspace, workspace_bytes, stream)`; `gateup_quant_last_error()`. The caller owns output, paired FP8 temp `[M,34816]`, native scale temp, CUTLASS workspace, and CUDA stream. Only `256<M<=32768`, exact shapes/dtypes/layouts, SM120, and opt-in target gate/up projection are eligible. Python must guard these conditions and fail closed; the C ABI validates pointers/M/swizzle but cannot validate tensor dtype/stride itself. No process-global mutable CUDA buffer is used; host-only launch context is thread-local.

The final synthetic gate covers 12 cases: candidate-active M=257,2741,2786,16160,32768; official fallback M=1,5,256; and M257 zero, tiny, large and exceptional inputs. All reported FP8-byte, FP32-scale-bit and downstream BF16 checks pass, and changed-input CUDA Graph replay passes on the normal active shapes. This is bounded synthetic evidence, not a model-quality test. In 31 paired graph-warm trials, the complete v6 GEMM+pack is slower than official GEMM+V2 quant: M16160 12.606 versus 10.509 ms, M2741 1.950 versus 1.777 ms, M2786 2.015 versus 1.802 ms, and M32768 25.295 versus 22.174 ms. Cold trials have the same direction. The 10.79-GiB packed-weight copy remains an explicit memory cost in both A/B arms. NCU and same-payload model A/B/A are separate evidence and must decide whether any narrower workload benefit exists; no whole-model gain is inferred from this microbenchmark.
